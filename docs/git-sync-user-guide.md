# 从 Git 仓库同步 Skill

把 Git 仓库里的 skill 同步到本平台。同步是**单向**的：平台只读取你的仓库，不会改动仓库里的任何东西。

> 面向日常使用者。运维配置（白名单、配额、环境变量）请看 [git-sync-guide.md](git-sync-guide.md)。

---

## 一、开始之前

1. **登录即可使用**，不需要额外申请角色。你注册的源只有你自己（和平台管理员）能看到和管理。
2. 你的 Git 主机需要被平台放行。如果保存时提示 **「仓库主机 xxx 不在允许范围内」**，把这句话发给平台管理员，让他加上你的主机名。

---

## 二、四步完成

1. **进入页面**：右上角头像菜单 →「Git 源管理」，地址是 `/sources`。（「发布技能」页右上角也有一个「从Git仓库同步」按钮，效果一样。）
2. **点「注册源」**，按下表填。
3. **点「试运行」**：它只预览会导入哪些 skill，不导入也不发布，可以反复点。预览还会标出**哪些目录同步时会失败**（重名、不是命名空间成员、技能已归档、文件数或体积超限、`SKILL.md` 写错等）；「预检」列显示问题条数，点一下看具体原因，一个目录可能有多条；会失败的目录在「变更」列直接写 **失败**。先按提示改掉再同步。
4. **点「立即同步」**：真正导入。导入的 skill 需要**审核通过**后才会对外可见、可下载。

| 字段 | 怎么填 |
| --- | --- |
| 仓库地址 | `https://github.com/owner/repo`、`git@gitlab.example.com:group/repo.git` 这类地址。不支持 `http://` |
| 分支或标签 | 想跟哪个分支就填哪个；**留空表示跟随仓库的默认分支**（GitLab/GitHub 上标为 default 的那个），默认分支不叫 `main` 也不会错。填错分支时**点保存就会提示**，并列出仓库里真实存在的分支名（还会猜你想填哪个），不用等到同步才发现 |
| 子目录 | 仓库里放 skill 的那一层目录，例如 `skills`；整个仓库就是一个 skill 时留空 |
| 凭据 | 公开仓库留空；私有仓库见第四节 |
| 目标命名空间 | 选一个你是成员的命名空间，导入的 skill 会放在这里 |
| 同步间隔（分钟） | 多久检查一次仓库变化，默认 60 |
| 定时同步 | 不想自动同步就关掉，之后手动点「立即同步」 |

---

## 三、仓库要长什么样

**每个「直接放着 `SKILL.md` 的目录」就是一个 skill**，`SKILL.md` 里必须有 `name` 和 `description` 两个字段。

**例 1：整个仓库就是一个 skill**（「子目录」留空）

```
my-skill/
├── SKILL.md
├── scripts/run.py
└── references/guide.md
```

**例 2：一个仓库放多个 skill**（「子目录」填 `skills`）

```
skills-repo/
├── README.md
└── skills/
    ├── pdf/SKILL.md      → skill「pdf」
    └── excel/SKILL.md    → skill「excel」
```

几点提醒：

* 「子目录」填了之后，只扫描这个目录里的内容。
* 如果仓库**根目录**也有 `SKILL.md`，它自己也会算一个 skill，并且会把整个仓库的文件都算进去。多 skill 仓库建议把「子目录」填成 skill 的上一层目录。
* 仓库里删掉某个 skill，平台上**已发布的 skill 不会被删除**，只是不再跟着仓库更新。
* 平台只接收常见文本/代码/图片/Office 文件，单个文件不超过 10 MB。被跳过的文件会写在「历史」里。

---

## 四、凭据怎么填

请使用**只读**凭据。**不要**用个人账号令牌或个人 SSH 私钥。

| 仓库类型 | 凭据填法 |
| --- | --- |
| 公开仓库 | 留空 |
| GitLab / 自建 GitLab（HTTPS） | `git:glpat-xxxxxxxx`（Deploy Token） |
| GitHub（HTTPS） | `x-access-token:<你的 PAT>` |
| Gitea（HTTPS） | `git:<部署令牌>` |
| SSH 地址（`git@host:path`） | 粘贴只读部署密钥的**私钥全文**（`-----BEGIN ... PRIVATE KEY-----` 开头） |

编辑已有源时：**留空 = 不改凭据**，填 `-` = 清除凭据。如果改了地址的协议（`https` ↔ `ssh`），需要重新填写凭据。

凭据不会在页面上回显，别人也看不到你的源。

## 五、界面上的按钮

| 按钮 | 作用 |
| --- | --- |
| 试运行 | 预览会「新增 / 变更 / 未变 / 移除」哪些 skill，标出预计会失败的目录及原因；「跳过文件」显示被平台拒收的文件数，点一下看清单，不导入 |
| 立即同步 | 马上同步一次 |
| 历史 | 每次同步的结果和说明（包括哪些文件被跳过） |
| 目录状态 | 仓库里每个 skill 目录当前的状态 |
| 编辑 | 改配置，从下次同步开始生效 |
| 删除 | 停止同步；**已经导入的 skill 会保留** |

列表最后一列能看到上次同步的结果：成功 / 部分成功 / 失败。

## 六、常见问题

**Q：同步显示成功了，为什么在技能列表里找不到？**
A：导入的版本是「待审核」状态，到目标命名空间的审核队列里通过后才会公开。

**Q：平台会自动发布、跳过审核吗？**
A：不会，一律走人工审核。

**Q：仓库里删掉一个 skill，平台上的会跟着删吗？**
A：不会。平台上已发布的内容保留，只是不再跟着仓库更新。

**Q：我改了仓库内容但没改 `SKILL.md` 里的版本号，会失败吗？**
A：不会，平台会自动生成一个新版本号并在「历史」里说明。想版本清晰，建议在仓库里正经改 `version`。

**Q：提示「仓库主机 xxx 不在允许范围内」怎么办？**
A：这是平台管理员配置的主机白名单，把提示原文发给他，让他把你的 Git 主机加进白名单。

**Q：提示「发布者不是命名空间成员」怎么办？**
A：你是建源人，必须先是目标命名空间的成员。让管理员把你加入该命名空间后再注册。

**Q：有些文件没被同步进来？**
A：平台只接收常见文件类型（文本、代码、图片、Office 文档等）且单个文件不超过 10 MB。被跳过的文件会记在「历史」里。

**Q：多久同步一次？**
A：按你设置的间隔。平台每 5 分钟检查一次有没有到期的任务，所以实际时间可能比间隔晚几分钟。

**Q：同一个仓库能接两次吗？**
A：可以——比如同一仓库的不同子目录，或导入到不同命名空间。但「地址 + 子目录 + 命名空间」完全相同的源只能有一个。

**Q：能把仓库里好几个目录都同步进来吗？**
A：一次只能填一个子目录。需要多个目录就建多个源（地址相同、子目录不同）。

**Q：同步要等很久？**
A：点「立即同步」后页面会等到这次同步结束；仓库很大时会慢一些。

**Q：我能看到别人注册的源吗？**
A：看不到。列表里只有你自己注册的源；平台管理员可以看到并管理所有人的源。同理，别人也看不到你的源和你的凭据。

**Q：提示「同一仓库地址、子目录与命名空间已存在源」怎么办？**
A：说明这个「仓库 + 子目录 + 命名空间」的组合已经有人注册过了（也可能是你自己之前建的）。换个命名空间或换个子目录，或者先确认那个源是不是你建的。

## 七、用 curl 调用接口同步

想用脚本或命令行自动化时用这套接口。权限和页面完全一样：**只能操作你自己注册的源**，别人的源一律返回 `未找到 Git 源`。

### 1. 准备 API Token

控制台 → **API Token**（`/dashboard/tokens`）→ 新建，把 token 复制下来（只显示一次）。git 源接口对所有有效 token 开放，不需要勾特殊权限。

```bash
TOKEN=你的-token
API=https://你的平台域名/api/v1/admin/git-sources
```

### 2. 查看自己有哪些源

```bash
curl -s -H "Authorization: Bearer $TOKEN" "$API"
```

只返回你自己注册的源（管理员能看到全部）。

### 3. 注册一个源

```bash
curl -s -X POST "$API" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoUrl": "https://github.com/owner/repo",
    "defaultRef": "main",
    "subpath": "",
    "namespaceSlug": "global",
    "credential": "",
    "syncIntervalMinutes": 60,
    "enabled": true
  }'
```

字段和页面表单一一对应：`repoUrl` 仓库地址、`defaultRef` 分支或标签（空 = 跟随仓库默认分支，即远端 `HEAD`）、`subpath` 子目录（空 = 整仓）、`namespaceSlug` 目标命名空间（必须是你是成员的命名空间）、`credential` 凭据（公开仓库填空）、`syncIntervalMinutes` 同步间隔分钟、`enabled` 定时同步开关。响应里的 `data.id` 就是这个源的 ID，后面都用它。

### 4. 试运行（只预览，不导入）

```bash
curl -s -X POST "$API/3/plan" -H "Authorization: Bearer $TOKEN"
```

看 `data.added` / `changed` / `unchanged` / `removed` 和 `items` 里的每个 skill 目录。

### 5. 立即同步

```bash
curl -s -X POST "$API/3/sync" -H "Authorization: Bearer $TOKEN"
```

这个请求会等这次同步结束再返回。看 `data.status`：`SUCCESS` 成功 / `PARTIAL` 部分成功（有目录失败）/ `FAILED` 失败。

### 6. 查看同步历史

```bash
curl -s "$API/3/runs?limit=5" -H "Authorization: Bearer $TOKEN"
```

### 7. 删除源

```bash
curl -s -X DELETE "$API/3" -H "Authorization: Bearer $TOKEN"
```

已导入的 skill 保留，只是不再跟着这个源更新。

### 常见问题

* 响应统一是 `{code, msg, data}`，`code = 0` 表示成功。
* 带了 `Authorization: Bearer` 头就不需要管 Cookie / CSRF。
* 接口路径里的 `/admin` 只是命名，普通用户同样能调——权限按"是不是你自己的源"判断。
* 生产环境把上面的 `你的平台域名` 换成正式的 https 域名，别用 `-k` 跳过证书校验。
